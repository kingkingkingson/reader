# 导出带批注的 PDF

把 Reader 中的 PDF 批注写进一份 PDF 副本，可在“预览”、Acrobat、Chrome、Zotero 等其他阅读器中查看。原文件不变。

## 入口

- 笔记栏 → 导出 → “导出批注与笔记”对话框底部的“导出 PDF”（仅 PDF）。
- 论文库或图书库中右键一份 PDF → “导出带批注的 PDF”。

导出期间显示进度提示，完成后显示写入的批注数；无法定位的批注单独说明数量。没有批注或全部无法定位时不保存文件。文件名为“标题-批注.pdf”，在 Electron 中弹出保存对话框。

## 写入方式

| Reader 批注 | PDF 中                                                   |
| ----------- | -------------------------------------------------------- |
| 高亮        | 同色高亮（半透明，正片叠底）                             |
| 下划线      | 每行底部 1.5 pt 的同色细条（与阅读器中 2 px 下划线一致） |
| 笔记        | 高亮，笔记内容写成评论                                   |
| 问题        | 高亮，评论为“问题：…”；已有 AI 回答时追加“回答：…”       |
| 书签        | 不导出（PDF 没有对应的批注类型）                         |

高亮附带的笔记同样写成评论。评论作者为“Reader”，时间为批注创建时间。

下划线写成高亮类型的细条而不是 Ink 线条：macOS“预览”（PDFKit）会把 Ink 批注画成白色，而高亮在 PDFKit 中按原色显示。

## 位置

- 原文上的批注保存的是相对于显示页面的矩形。导出时只合并同一行上相交或紧邻的框（`getClientRects()` 会返回重叠的重复框），双栏中同一高度的左右两栏保持分开；再用 PDF.js 视口换算回 PDF 坐标，因此带 `/Rotate` 的页面和原点不在 (0, 0) 的 MediaBox/CropBox 都落在正确位置。
- 译文上的批注只保存了原文段落的范围。导出时在段落内的 PDF 文字中查找对应的原文句子（与阅读器联动高亮使用同一套句子匹配），只覆盖这些句子，不会把整段标亮。
- 一次选中多个译文段落（可跨页）时，按 `translation.ranges` 中的每个段落、借助版面块的页码与范围分别定位，每页写一条批注，评论只写在第一页那条上。每段的原文句子来自句子联动记录；关闭了译文批注联动、没有句子记录的跨段选区无法定位。
- 一条批注要么完整写入，要么整体跳过并计入“无法定位”，不会只写入其中一部分。

## 实现

`apps/web/src/readers/pdf-export.ts` 通过 PDF.js 的 `annotationStorage` 写入新批注，再用 `saveDocument()` 做增量保存：原始字节保持为文件前缀，新对象和交叉引用追加在末尾，已有的 PDF 批注和书签保留。高亮带外观流，不依赖阅读器自行生成。`apps/web/src/annotated-pdf-export.ts` 读取批注与对话（问题的回答），按需加载 PDF.js 后导出并下载。

PDF.js 新建批注的数据格式属于其内部格式（`pdfjs_internal_editor_` 前缀与编辑器序列化字段），升级 `pdfjs-dist` 时由测试兜底。

## 验证

自动测试用真实 PDF.js 导出再重新打开：高亮颜色与评论、问题与回答、下划线细条的位置与厚度、书签与越界页跳过、原始字节为前缀；旋转 90° 且 MediaBox 有偏移的页面坐标；译文批注只覆盖原句、找不到时跳过；导出入口的批注筛选、回答映射、文件名与提示。

已用 macOS PDFKit（与“预览”相同）渲染导出的样例，确认高亮、下划线细条和译文批注的位置与颜色。

手动检查：

1. 在一篇 PDF 上分别做高亮、下划线、带笔记的高亮、问题（含 AI 回答），并在译文上划一句高亮。
2. 从笔记栏导出对话框和库中右键分别导出，确认提示的数量。
3. 用“预览”、Chrome、Acrobat 打开副本，检查位置、颜色和评论内容；原文件不变。
4. 对扫描版或旋转页面的 PDF 重复一次。
