## 合并后简化扫描

用户要求以“概要＋阅读位置＋按需工具读取”为准，去掉合并主线时保留的冗余上下文链路。本轮检查了设置、客户端构造、阅读器接口、服务端提示词、会话、能力检测与协议说明。

| 删除或简化                               | 原因                                                                                |
| ---------------------------------------- | ----------------------------------------------------------------------------------- |
| 自动附章开关及配置／OpenAPI／生成类型    | 文档 Agent 已能自主读取，不需要第二种自动附章策略；旧本地配置字段忽略，模型连接保持 |
| 选区自动扩章、附近段落截取、超长确认弹窗 | 只发送主动选区；无需先扩展大量原文再裁剪；显式引用仍有 UTF-8 256 KB 硬上限          |
| getChapterContext 与 quoteSectionRange   | 仅服务于自动扩章，已无生产调用；翻译用的 chapterRange 保留                          |
| 全篇批注自动拼接                         | 与用户这次主动引用无关；批注问题仍发送自己的问题和选区                              |
| 图片附件附加当前页文字                   | 用户只附图片时，不读取无关当前页正文                                                |
| Agent 前置构造旧式完整历史提示词         | 持久会话直接使用结构化历史；仅兼容路径需要时才构造旧式提示词                        |
| 生成概要与元数据摘要重复提供             | 优先生成概要，缺失时才使用元数据摘要；摘要也不算原文摘录                            |
| 目录解析中会被覆盖的工具能力赋值         | 文档工具与读图能力只采用实际工具检测的结果                                          |
