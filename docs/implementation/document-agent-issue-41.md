# #41 文档 Agent 第一阶段与奥卡姆审查

日期：2026-10-14。范围：用户授权的 Codex 与 DeepSeek API 全文检索、原文读取、自主多步问答；复用既有解析及 CLI 登录。分支 `codex/issue-41-agent-design`，基线 `3aa18a5`；主 checkout 保持 `main` 的 `a37b6bf`，未推送。

## 最小实现与复用

一次全文问答需要可查询的原文、读取工具、下一步决策和最终答案保存。现有 PDF／EPUB 解析已经提供原文，新增代码只补后面这些能力及未解析页面的文字来源。

| 检查项    | 审查后的实现                                                                                                                  |
| --------- | ----------------------------------------------------------------------------------------------------------------------------- |
| PDF 原文  | 先 `readLayout`，直接使用已有 Text／bounds；只有未解析页面才执行文字提取。完整缓存即使 worker 不存在也能问答。                |
| EPUB 原文 | 复用 `readEPUBBlocks` 和清洗后 readingOrder；保留 href、locator、UTF-16 原生位置。                                            |
| 检索      | SQLite FTS5 段落索引与 BM25、中文精确子串补召回。旧 `search_index` 服务于 EPUB 资源搜索，继续使用；没有替换它或新增向量服务。 |
| 工具      | 一个 Go 处理器提供 `get_outline`、`search_document`、`read_passage`，Codex MCP、API 循环及检索辅助模式共用。                  |
| API SSE   | 删除新路径另写的 framing 代码，普通回答和工具轮共用 `consumeCompletionFrames`；各自保留必要的正文／参数消费语义。             |
| 用量统计  | 普通生成、API 读取轮及 Codex 读取／成文共用 `trackModelUsage`；删除纯转发包装，不重复计算多轮请求。                           |
| Codex RPC | 配置探测和生成共用 session 的 RPC 读取、调用及初始化；没有第二套 JSON-RPC 框架。                                              |
| MCP       | 使用官方 Go SDK v1.8.0，复用其 localhost Host 保护，额外绑定本次文档令牌及取消信号。                                          |
| 多步问答  | Codex 使用原生循环；API 使用最多 8 轮的结构化工具循环，没有通用 Planner、文本 Thought/Action 解析或新 Agent 框架。            |

首版保留 3 个工具、每次问答最多 16 次工具调用、48 KiB 独立原文证据、单次工具结果最多 12 KiB。这些限制与现有 3 分钟交互请求预算一起约束运行。

两阶段输出有明确用途：阅读阶段不向正文发送模型中间说明，成文阶段禁用工具并复用现有增量回答流；完整上游结束、来源校验及数据库事务成功后才发送唯一 `done`。取消、删除、断流和失败不会保存成功助手答案。可选 `activity` 事件已同步流式约定、OpenAPI、SDK、前端及共用回放 fixture。

## Codex 与 DeepSeek

Codex 使用现有 CLI 登录：先通过 `config/read` 取得继承 MCP 名称，结束探测进程；工作进程逐项设置 `enabled=false` 并添加本次 Reader MCP。启动前后复核配置，创建 thread 后检查运行时 MCP 工具；成文使用独立无文档工具进程。Reader 不修改全局配置，不读取或复制 CLI 凭证。含该版本无法准确覆盖的 MCP 名称或工具范围不符时明确失败。

DeepSeek 使用现有 Chat Completions 请求路径。工具调用参数完整组装、成功结束后才执行；下一轮同时回传 assistant 调用、`tool_call_id` 和 opaque `reasoning_content`。续接字段不显示或落库为推理。工具检测采用随机 nonce 往返，工具 schema 指纹单独校验；文本能力和工具能力互不代替。未检测或不支持工具的模型使用共享处理器做检索辅助回答，界面明确显示该模式。

来源 ID 由服务器生成。搜索摘要不直接成为证据，`read_passage` 的原文、语料版本、哈希和原生位置才进入来源记录；未知 `[Sx]` 引用拒绝保存。点击已保存来源时重新校验版本，避免跳转到同 ID 的新内容。已有表格、公式块即使带图片，只要包含原文文字也保留，二维结构的限制随覆盖信息提供给模型。

## 后续修正：索引前移与工具状态 · 2026-10-14

用户指出每次提问都出现“准备全文原文”，并要求像 Codex 一样显示工具正在查看的具体目标。原实现按首次提问构建索引，且在缓存检查前固定发送准备状态，造成缓存命中也显示同样提示。

现在导入事务记录后台索引任务，沿用 `StartProcessing` 的生命周期及文档取消／删除机制；EPUB 导入后、未启动版面解析的 PDF 在后台准备。PDF 版面任务排队或运行时，后台索引等待已有解析；解析完成后直接使用已解析原文建立索引，再进入翻译。队列只保存 documentId／status，成功移除、失败保留而不每秒重复提取，重启恢复中断任务。关闭自动翻译仍保持暂停，不会因索引启动 AI 或恢复翻译。

提问先检查有效缓存，命中不发送准备状态，也不会被其他文档的索引构建锁阻塞；缺失或过期时才显示“正在建立全文检索索引”并补建，保留旧文档和导入未完成时的兼容路径。

工具执行前通过原有 `activity` 事件发送具体目标及用途：查看目录／定位章节、检索关键词／查找原文、查看页码或章节／阅读相关段落。关键词及章节名作为不可信文字清理控制字符并限长；不显示推理或完整参数。前端用静止的 Lucide BookOpen 图标和一行灰色文字显示，超长省略并可悬停查看全文；最终正文开始后清除工具状态。

新增回归覆盖导入后首次问答前索引就绪、PDF 解析直接建立索引、缓存命中不触发准备、暂停翻译不被恢复、中断任务恢复及删除清理，以及工具目标和活动状态与最终正文分离。类型检查、全量测试和构建通过；Vitest 更新为 597 通过、4 跳过，相关 Go race 测试通过。本轮没有额外真实模型调用，界面效果由独立预览人工确认。
