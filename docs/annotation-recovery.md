# 译文批注重译恢复

打开文档时调用 `POST /api/documents/{id}/annotations/recover`，随后读取批注。`annotation_recovery.checked` 按文档保存；缺少记录等同于 0。成功检查和批注更新在同一事务内提交并置 1。开始全文重译及发布翻译记录时置 0。为 1 时跳过恢复搜索，正常高亮绘制仍执行。侧栏“重新定位”用 `force: true` 主动重试。

服务端让同一文档的全文重译请求与批注检查互斥，检查期间也锁住批注修改及译文发布。检查超时为 5 秒；已检查文档不等待恢复锁，其他锁被占用时直接返回繁忙，不排队；取消、超时或数据不完整时回滚，不能把暂时缺失的数据作为删除依据。重新翻译尚未完成时不检查。撤销批注修改后置 0，避免撤销重新引入的旧记录跳过检查。正在阅读的文档不会因进度更新重复检查，下次打开时再检查。

## 恢复规则

- 新批注保存对应原文句子和整段旧译文上下文（前句长度变化也会移动段内偏移）；重译前为仍有效的旧记录补充上下文。
- 先以段落 ID 和原文哈希确认段落。解析后段落编号变化时，使用原页／章节内唯一的原文哈希或原文摘录确认段落。
- 根据原文范围映射新句子，允许句子合并或拆分。不把旧句子序号单独作为历史恢复依据。
- 词语先精确搜索，再忽略空白和全角形式搜索。四字符以上的非纯数字选区可以按编辑距离做局部匹配，最低相似度 60%。同分选择最靠前的位置，同起点优先长度接近原选区的结果。
- 局部匹配失败则高亮对应整句。没有原句上下文时，在确认的段落内选择最相似的一句；不再因句子相似度低而放弃。原来选中了整句的批注继续覆盖对应整句。
- 原段落也无法确认时删除译文记录；跨段批注保留仍可确认的范围。解析未完成、失败页和未完成译文不会触发删除。
- 保存的原始摘录、笔记、标签、颜色、创建时间不因定位改变。显示、悬停、点击和跳转使用恢复后的定位。

## 旧版双侧记录

存在 `sentenceLink` 的旧版双侧记录拆成独立原文、译文两条。创建侧保留原 ID，另一侧生成新 ID；其他元数据复制。移除旧双侧标记与创建新记录在同一事务内完成，重复检查不会重复拆分。

从译文创建的旧 PDF 双侧记录可能只有整段原文矩形。拆出的原文记录使用独立 `sourceAnchors` 保存原句及页内范围，由 PDF.js 定位原句，PDF 导出也使用相同原句，不把整段矩形当成精确高亮。

旧版 EPUB 译文记录与新版单侧译文记录没有可区分的持久化标记。无明确 `sentenceLink` 的记录保持单侧，避免给新版单侧批注增加另一侧高亮；不使用时间戳猜测版本。

## 验证

服务端测试覆盖历史数据拆分、幂等性、重译前保存上下文、句子拆分、整句回退、段落重新编号、孤立记录删除、未解析页面保护、取消回滚、互斥、flag 跳过及重开数据库后的持久化。前端测试覆盖格式化文字、重复词、整句范围、独立原文句子绘制、打开时调用顺序及 PDF 导出。

手工验收：打开有旧批注的论文，核对拆出的两条记录可分别删除；重译后重新打开，核对词语／整句高亮和侧栏跳转；点击“重新定位”可主动检查。无需为自动化验证启动 UI。
